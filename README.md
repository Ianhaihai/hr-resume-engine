# HR Resume Engine · AI 简历工作台

> 面向 HRBP / 招聘方的秋招简历提效工具：用 AI 把"人肉翻简历"变成"做判断"。

---

## 一、这个项目在解决什么痛点

秋招期间，一个 HRBP 岗位动辄收到几百上千份简历。传统模式下，初筛靠人工逐份翻阅、匹配靠经验、给候选人改简历靠手感——**时间被淹没在重复劳动里，真正有价值的"判断"反而没时间做**。

本项目把三个高频动作交给 AI 完成，让人力资源从业者把精力从"读简历"转向"做决策"：

| 场景 | 传统做法 | 本工具 |
|---|---|---|
| 简历初筛 | 人工逐份翻、凭感觉排 | 批量解析 → 按岗位 JD 自动打分排序 |
| 人岗匹配 | 经验判断、难向上汇报 | 输出匹配度 + 优势/差距 + 推荐理由 |
| 简历丰富（帮候选人/员工改简历） | 靠个人手感、不可复用 | 按 STAR 法则生成有数据、有成果的专业表述 |

---

## 二、核心能力

1. **简历解析**（`ai_parse.py`）：把一份简历文本解析成结构化字段（姓名、学历、实习经历、技能等）。
2. **简历丰富**（`enrich.py`）：按 STAR 法则，把单薄经历扩写成有数据、有成果的专业表述——HRBP 帮候选人/内部员工做简历反馈的 B 端刚需。
3. **岗位匹配诊断**（`match.py`）：对照一条 JD，输出综合匹配度、优势项、差距项与一句推荐理由。
4. **批量初筛排序**（`screen.py`）：一次性处理多份简历，按岗位匹配度从高到低排序，HRBP 只需重点看前几名。

## 三、产品闭环

```
     简历/ JD 文本
          │
          ▼
   ┌──────────────┐
   │  简历解析      │  文本 → 结构化卡片
   └──────────────┘
          │
          ▼
   ┌──────────────┐
   │  人岗匹配/打分 │  简历 vs JD → 匹配度 + 理由
   └──────────────┘
          │
          ▼
   ┌──────────────┐
   │  简历丰富      │  STAR 扩写薄弱经历
   └──────────────┘
          │
          ▼
   批量排序 → 初筛名单 → HRBP 决策
```

AI 在闭环里干"脏活累活"，**人只做最终判断**——这是工具的设计内核。

## 四、技术架构（极简、零运维、可零成本运行）

- **语言**：Python（标准库 + `requests` + `streamlit` + `pymupdf`）
- **AI 能力**：阿里云百炼 / 通义千问（OpenAI 兼容模式），通过 API 调用
- **运行成本**：使用平台免费额度即可跑通 demo，**无需付费**
- **架构亮点**：
  - 统一 AI 调用入口 `llm.py`：有 Key 走真实大模型，无 Key 自动降级为"演示模式"，保证流程不中断
  - 所有 AI 调用均要求**结构化 JSON 输出**，便于下游处理
  - 网页界面 `app.py`（Streamlit）：支持 PDF 上传、多岗位切换、批量初筛、结果导出，贴近真实使用场景
  - 纯本地 + 免费 API，无需数据库、无需服务器

---

## 五、合规设计（重要）

简历属于《个人信息保护法》下的敏感个人信息，本项目在设计与演示上遵循以下原则：

- **演示数据全程脱敏**：`Data/samples/` 中的简历与 JD 均为虚构样本，不含任何真实个人信息。
- **防歧视约束**：匹配 / 打分提示词中显式要求**仅依据学历、专业、经历、技能、成果等岗位相关要素打分，严禁使用性别、年龄、籍贯、婚育、照片等受保护特征**——这是 AI 用于招聘场景的合规底线。
- **人工决策优先**：AI 输出为"建议"，最终录用决策由 HRBP 做出。

## 六、快速开始

### 1. 环境准备

```bash
# 需要 Python 3.10+，验证安装
python3 --version
```

安装依赖：

```bash
python3 -m pip install requests streamlit pymupdf
```

### 2. 配置大模型 Key

本项目使用阿里云百炼（通义千问）。获取 API Key 后，在项目根目录创建 `.env` 文件：

```bash
echo "LLM_API_KEY=sk-你的key" > .env
```

> ⚠️ `.env` 已被 `.gitignore` 忽略，密钥**不会**被提交到 GitHub。

### 3. 运行（网页界面，推荐）

无需改代码、无需命令行，直接打开浏览器操作：

```bash
python3 -m streamlit run app.py
```

打开终端提示的本地地址（默认 http://localhost:8501），即可：
- 左侧**粘贴岗位 JD**（或上传多个 JD 文件自由切换岗位）
- 右侧**批量上传 PDF / TXT 简历**
- 点「开始匹配初筛」→ AI 自动解析并按匹配度排序，输出初筛名单，可**一键导出 CSV**

### 4. 运行（命令行脚本）

```bash
python3 ai_parse.py   # 解析单份简历
python3 enrich.py     # 简历丰富（STAR 扩写）
python3 match.py      # 岗位匹配诊断
python3 screen.py     # 批量初筛排序（读取 Data/samples/ 下多份简历）
```

未配置 Key 时会自动进入"演示模式"，仍可查看完整流程。

## 八、给他人 / 面试官：如何从 GitHub 运行本项目

本项目已开源。任何人获取代码后，按以下步骤即可在本地跑起来：

```bash
# 1. 获取代码（二选一）
git clone https://github.com/Ianhaihai/hr-resume-engine.git
cd hr-resume-engine
# 或直接下载 ZIP 解压

# 2. 安装依赖（一次性）
python3 -m pip install -r requirements.txt

# 3.（可选但推荐）配置自己的大模型 Key
echo "LLM_API_KEY=sk-你的key" > .env

# 4. 启动网页界面
python3 -m streamlit run app.py
```

- **没有 Key 也能跑**：未配置 `.env` 时自动进入"演示模式"，可完整体验界面与流程（输出为示例文案），方便快速了解产品形态。
- **真实 AI 能力需要自己的 Key**：Key 是私有的，不会随仓库分发；请自行在阿里云百炼注册获取免费额度。
- 启动后浏览器打开 http://localhost:8501，即可上传 PDF 简历、切换岗位 JD、查看匹配排序并导出 CSV。
